1. Programmer

Update the programmer's firmware
  1. Firmware file
  2. Put the programmer in bootloader mode
    If that button is disabled (older firmware, or the programmer does not connect): unplug it, hold the BOOT button on the RP2350-Zero (BOOTSEL on a Pico) while plugging it back in, then release.
  3. Connect to the bootloader
    In the browser's list, pick the RP2 / RP2350 boot device. If one was already allowed earlier, the page connects to it by itself.
  4. Write

No luck with the steps above? Download the firmware (.uf2)Download the firmware from the project's releases, put the programmer in bootloader mode as in step 2, and drag the file onto the drive that appears (RPI-RP2 or RP2350).

2. Tag

Put the tag on the fixture so the pogo pins touch its pads, then Detect. Back up before you write anything: flashing the BLE firmware replaces the Hanshow bootloader, and your backup is the only way back to the original firmware.

Browser

  
Use a Chromium-based desktop browser (Chrome, Edge, Brave, Opera, Chromium). The page needs
    Web Serial to talk to the programmer and WebUSB to update the programmer's firmware.
    Firefox and Safari have neither, and mobile browsers are not supported. The page must be opened
    over https or from localhost.


  
Linux permissions

  
The programmer is a USB serial device (/dev/ttyACM*). If connecting fails with
    "could not open the serial port", either add yourself to the serial group
    (dialout on Debian/Ubuntu/Fedora, uucp on Arch) and log in again, or
    install a udev rule. The same rule file should also cover the RP2040/RP2350 bootloader, which
    WebUSB needs write access to when updating the programmer:

  
# /etc/udev/rules.d/60-stellar-prog.rules
# pico-sws programmer: serial ports for the logged-in user; keep ModemManager off them
SUBSYSTEM=="tty", ATTRS{idVendor}=="2e8a", ATTRS{idProduct}=="000a", TAG+="uaccess", ENV{ID_MM_DEVICE_IGNORE}="1"
# RP2040 and RP2350 USB bootloaders (PICOBOOT), for updating the programmer
SUBSYSTEM=="usb", ATTRS{idVendor}=="2e8a", ATTRS{idProduct}=="0003", TAG+="uaccess"
SUBSYSTEM=="usb", ATTRS{idVendor}=="2e8a", ATTRS{idProduct}=="000f", TAG+="uaccess"

  
Then run sudo udevadm control --reload-rules && sudo udevadm trigger and replug.


  
When something goes wrong

  
    
    
  • No reply from the tag: the pogo pins are almost always the reason. Press the tag
      flat onto the fixture and try again.
    • 
    
  • "That was the programmer's UART port": the programmer shows up twice in the browser's
      list. Click Connect again and pick the other entry.
    • 
    
  • A write stopped half way: nothing is lost while the tag stays on the fixture. Run the
      same write again; sectors that are already right are skipped.
